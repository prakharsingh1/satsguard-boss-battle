SATSGUARD / FIELD GUIDE

The proposal and the promise.

A PSBT describes a proposed Bitcoin transaction. Your intent describes what you meant to pay. SatsGuard compares the two locally, using deterministic rules. It is a hackathon prototype, not a trusted signing device.

Run a check

  1. Load one of the four clearly labeled synthetic examples, or paste a BIP174 PSBT v0 as base64 or hex. A binary .psbt file can be loaded locally.
  2. Select the address network. Enter every expected payment in whole satoshis. One Bitcoin is 100,000,000 satoshis.
  3. Explicitly list allowed change addresses and set a maximum absolute fee. Change is never guessed from PSBT derivation metadata.
  4. Run preflight. Read the output map and all observations. A missing input amount leaves the fee unknown.
  5. Export a redacted JSON report for issue reports or agent integrations. Amounts, counts, findings and network remain; identifiers are removed.

What the result means

Declared checks failed: an unexpected output, incorrect payment total, fee above your cap, or inconsistent supplied transaction data was detected.

Review required: a declared check could not be completed or metadata needs attention. Missing input values cannot pass the fee cap check.

No declared checks failed: the checked outputs and supplied values satisfy your declared policy. This is not proof that the transaction is valid or advisable.

Input values are supplied PSBT claims, not chain-verified balances. A declared change address is an allowlist entry, not proof that you own it. Addresses validate against the selected network, but unsigned transaction bytes contain no network marker.

For agents and automation

The CLI uses the same engine as the browser. It emits redacted JSON to stdout and returns exit 2 for blocked checks or invalid input, exit 1 for review, and exit 0 when no declared checks failed. Treat exit 0 as completion of this limited policy check.

npm ci
npm test
node scripts/cli.mjs --psbt proposal.psbt --intent intent.json

Intent schema:

{
  "network": "testnet",
  "payments": [
    { "address": "YOUR_TESTNET_RECIPIENT", "amountSats": "50000" }
  ],
  "changeAddresses": ["YOUR_DECLARED_CHANGE_ADDRESS"],
  "maxFeeSats": "2000"
}

Privacy boundary

There are no analytics, remote fonts, account prompts, remote APIs, keys, signing or broadcasting controls in the application. It does not store your inputs in local storage. The hosting provider receives normal page requests; pasted transaction data is processed in memory in your browser. For stronger isolation, run the source locally and disconnect the network after loading it.

Redaction removes addresses, scripts, outpoints, keys, derivation paths and raw PSBT content through an allowlist. It does not anonymize amounts, transaction shape or findings. Review reports before sharing them.

Deliberate limits

  • PSBT v0 only; version 2 is explicitly rejected.
  • No chain-state lookup, signature validation, wallet ownership proof, signing-policy verification, dust policy or exact fee-rate calculation.
  • Taproot spending policy, script execution and signature coverage are not verified.
  • Metadata is observed and warned about, not sanitized from the original PSBT. SatsGuard never modifies a proposal.
  • Synthetic examples use invented outpoints and public-key hashes. They contain no real funds.

Protocol and attribution

Built using bitcoinjs-lib for PSBT, transaction and address parsing, with an extra strict envelope check and an original intent policy engine. Protocol references: BIP174, BIP371.
